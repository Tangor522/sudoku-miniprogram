## 一、登录模块（BB-LOGIN）

### 等价类
| 有效等价类 | 无效等价类 |
|---|---|
| 首次进入（云环境就绪，库无记录） | 云环境未开通（降级本地用户） |
| 老用户带昵称（直接进入） | 网络异常（callFunction 失败） |
| 老用户无昵称（需补全资料） | 重复快速点击登录（防抖） |

### 用例
- **BB-LOGIN-01（P0 有效）** 云环境就绪、首次进入
  - 步骤：冷启动 → 点击「微信一键登录」
  - 预期：`isNew=true`，写入 `users` 一条，`globalData.user` 有值，跳转首页；本地缓存 `currentUser` 存在。
- **BB-LOGIN-02（P0 有效）** 老用户带昵称
  - 步骤：已登录过用户，清除本地缓存后重新登录
  - 预期：返回原昵称，不弹资料补全页，直接进入首页。
- **BB-LOGIN-03（P1 有效）** 老用户无昵称
  - 步骤：云库 `users.nickName` 为空时登录
  - 预期：弹出资料补全（昵称/头像）页，`update=true` 回写后进入首页。
- **BB-LOGIN-04（P1 边界）** 云环境未开通
  - 步骤：`app.js` 的 `cloudEnv` 为空，登录
  - 预期：生成 `local_xxx` 临时用户，本地存储可用，首页可正常玩游戏（排行榜/PK 不可用，给出提示）。
- **BB-LOGIN-05（P1 异常）** 网络异常
  - 步骤：断网后点击登录
  - 预期：toast 提示「登录失败，请重试」，停留在登录页，不闪退。
- **BB-LOGIN-06（边界）** 重复快速点击
  - 步骤：连续快速点 3 次登录按钮
  - 预期：只发起一次登录流程，不产生重复 `users` 记录。

## 二、单人解题（BB-SOLO）

### 等价类
- 模式：4x4（有效）、6x6（有效）
- 关卡：第 1 关（易）/ 中段关 / 第 51+ 关（4x4 最大挖空 12）/ 第 51+ 关（6x6 最大 19）
- 输入：合法数字、非法（冲突）数字、擦除、撤销
- 胜负：正确填满 → 胜；留空/冲突 → 不判胜

### 用例
- **BB-SOLO-01（P0 有效）** 4x4 正确通关
  - 步骤：进入 4x4 → 逐格填正确解 → 填最后 1 格
  - 预期：最后一格填入且全盘无冲突 → 弹通关弹框（秒表格式成绩），关卡 +1，成绩写入。
- **BB-SOLO-02（P0 有效）** 6x6 正确通关
  - 步骤：同上 6x6
  - 预期：同 BB-SOLO-01；键盘数字大小与单人模式一致（回归两项修复点）。
- **BB-SOLO-03（P0 边界）** 末格填错不判胜
  - 步骤：前 N-1 格正确，最后 1 格填冲突值
  - 预期：`hasError=true`，不弹通关框，错误格高亮。
- **BB-SOLO-04（P1 边界）** 最大难度关仍可解
  - 步骤：4x4 第 51 关（12 空）/ 6x6 第 51 关（19 空）
  - 预期：生成的题目为合法残局（无预置冲突），可正常完成。
- **BB-SOLO-05（P1 功能）** 成绩「只快不慢」
  - 步骤：同一关先 100s 通关（存 100），再 50s 通关（覆盖为 50），再 80s 通关（保持 50）
  - 预期：最终记录为 50s（与 storage 单测逻辑一致）。
- **BB-SOLO-06（P1 功能）** 撤销/擦除
  - 步骤：填数 → 撤销 → 擦除
  - 预期：状态正确回退，无残留错误标记。
- **BB-SOLO-07（边界）** 切后台再回前台
  - 步骤：游戏中切后台 30s 再回前台
  - 预期：计时暂停期间不计入，回前台继续（timer 后台自动暂停）。

## 三、计时器（BB-TIMER）

### 边界值（对应 `formatStopwatch`）
| 输入(ms) | 预期显示 | 类型 |
|---|---|---|
| 0 / 负数 / undefined | `00:00.0` | 边界 |
| 59900 | `00:59.9` | 正常值 |
| 60000 | `01:00.0` | 进位边界 |
| 610400 | `10:10.4` | 正常值 |
| 3599999 | `59:59.9` | 上限边界 |
| 1234 | `00:01.2`（截断非四舍五入） | 边界 |

### 用例
- **BB-TIMER-01（P1）** 秒表展示一致性：通关弹框时间须为 `MM:SS.d` 格式（回归第二项修复点）。
- **BB-TIMER-02（P1 边界）** 计时精度：游戏中计时刷新流畅（50ms tick），`getSeconds` 为向下取整。
- **BB-TIMER-03（P1）** 新开局重置：进入新一关，计时归零重新计数。

## 四、排行榜（BB-RANK）

### 等价类
- 数据规模：空列表 / 单条 / 多条
- 排序：总关数降序；总关数相同则总用时升序
- 自身排名：`myRank` 命中 / 未上榜

### 用例
- **BB-RANK-01（P1 边界）** 空榜单
  - 预期：列表为空，`myRank=null`，不报错。
- **BB-RANK-02（P1 功能）** 排序正确
  - 构造：A 总关 10/用时 200，B 总关 12/用时 300，C 总关 12/用时 100
  - 预期：顺序 B? 不——`totalLevels` 降序优先：B、C（12 关）在前，A（10 关）在后；B、C 同关数按用时升序 → C(100) 在前、B(300) 在后。
  - 最终顺序：C → B → A。
- **BB-RANK-03（P1 边界）** 昵称缺失
  - 预期：`users.nickName` 为空时显示「匿名玩家」。
- **BB-RANK-04（P1 边界）** 自身排名高亮
  - 预期：当前用户所在行 `myRank` 正确高亮，未上榜时不崩溃。

## 五、PK 对战（BB-PK）

### 等价类
- 匹配方式：随机匹配 / 房间号邀请
- 总局数：`totalRounds=1`（最小）/ 中段 / `=5`（最大）/ `=0` 或 `=9`（应被钳制为 1~5）
- 准备：单方准备不开始 / 双方准备才开始
- 推进：独立推进，先完成全部 N 局者胜
- 提交：正确前进 / 冲突错误 / 留空未完成 / 已结束后提交
- 局面：认输 / 断线重连 / 并发到达终点

### 用例
- **BB-PK-01（P0 功能）** 随机匹配双人开局
  - 步骤：A 点随机匹配 → B 点随机匹配
  - 预期：A 建 waiting 房间，B 加入后 `status=playing`，生成 N 局题目，双方 `playerStates` 初始化。
- **BB-PK-02（P0 边界）** 房间号邀请
  - 步骤：A 创建房间拿到 6 位码 → B 输入码加入
  - 预期：B 成功加入；输错码提示「房间不存在」；第三人无法加入已开始房间。
- **BB-PK-03（P0 边界）** 总局数钳制
  - 步骤：传入 `totalRounds=0` → 应为 1；传入 `=9` → 应为 5。
- **BB-PK-04（P0 功能）** 准备阶段
  - 步骤：A 点「准备开始」，B 未准备
  - 预期：单方准备不进入游戏；双方都准备后才开始（回归修复点）。
- **BB-PK-05（P0 功能）** 独立推进、先到先赢
  - 步骤：A 连完成 N 局，B 还在第 2 局
  - 预期：A 先完成 → A 胜，双方 `pk_records` 各写入一条；B 迟到的提交被拒「已结束」。
- **BB-PK-06（P0 边界）** 提交校验
  - 正确完成当前局 → 进入下一局；
  - 改动题目固有格（与 puzzle 不符）→ 返回 `error` 含「题目」；
  - 留空（洞未填）→ `reason:'wrong'`。
- **BB-PK-07（P0 功能）** 认输判负
  - 步骤：A 在游戏中认输
  - 预期：对手 B 获胜，对局结束。
- **BB-PK-08（P1 功能）** 断线/重连
  - 步骤：A 断网 → 重连
  - 预期：重连后能恢复对局状态；仅显示进度条，不显示对手棋盘（防作弊回归点）。
- **BB-PK-09（P1 边界）** 并发到达终点
  - 步骤：A、B 同一毫秒提交最后一局
  - 预期：事务保证仅一次结算，无重复写入 `pk_records`。
- **BB-PK-10（P1 功能）** 战绩与统计
  - 步骤：完成若干对局后进入战绩页
  - 预期：`list` 按 `finishedAt` 倒序；`stats` 聚合胜/负/平、模式分布、胜率、总时长、平均时长正确。
